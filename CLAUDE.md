# CLAUDE.md — Agent Guide for `flutter_template`

> Source of truth for AI agents (Claude Code / Cowork) working in this boilerplate.
> Based on https://github.com/nizwar/flutter_template. Read this file **before** writing code.
> See also `readme.md` (human guide) and `DEEP_CHECK_REPORT.md` (known technical debt).

---

## 1. What this is

A Flutter boilerplate built on Provider + go_router + Dio + Firebase. The contents of this repo are meant to live **inside the `lib/`** folder of a Flutter project (there is no `pubspec.yaml` at the template root). `firebase_options.dart` is `.gitignore`d and generated by `flutterfire configure`.

Core stack: `provider`, `go_router`, `dio`, `equatable`, `shared_preferences`, `cached_network_image`, `shimmer`, `ndialog`, `pull_to_refresh_flutter3`, `intl`, `firebase_core/analytics/crashlytics/performance`.

## 2. Golden rules (do not break)

1. **Preserve the `core/` vs `ui/` split.** Logic & data in `core/`, presentation in `ui/`. Never put widgets in `core/` or networking in `ui/`.
2. **Never hardcode colors.** Always go through `ThemeData`/`ColorScheme`. Use the `theme(context)`, `textTheme(context)`, `colorScheme(context)` helpers from `core/resources/themes.dart`. Custom colors → the `CustomColors` extension in `core/resources/colors.dart`.
3. **Zero warnings.** No deprecated/unused imports. Run `flutter analyze` & `dart fix --apply` before finishing.
4. **Reuse first, build new later.** Check `ui/components/` and `core/utils/` before creating a new widget/util.
5. **Minimal, consistent diffs.** Keep the folder structure and naming conventions. No large refactors unless asked.
6. **Use `const` wherever possible** on widgets to minimize rebuilds.

## 3. Directory map

```
lib/
├── main.dart                    # entry; init Firebase + Crashlytics; MultiProvider; MaterialApp.router
├── root.dart                    # Root: postFrameCallback → loads theme → context.goNamed("home")
├── core/
│   ├── https/http_connection.dart   # abstract HttpConnection + ApiResponse + HttpErrorConnection
│   ├── models/model.dart            # abstract Model (Equatable) — every model extends this
│   ├── providers/                   # global providers (ThemeProvider, UserProvider)
│   ├── resources/                   # colors, themes, styles, environment (AppConfig subclasses)
│   └── utils/                       # app_config, route (go_router), navigations, preferences, logger, utils, extensions
└── ui/
    ├── screens/                     # MainScreen, SplashScreen, etc.
    └── components/                  # reusable widgets (CustomCard, CustomImage, PaginatorPage, ...)
```

## 4. Required patterns per type of work

### Model — `lib/core/models/`
Extend `Model`, implement `toJson()` and `fromJson`. Note: `Model.props` currently defaults to `[toString()]` (see report §2.4); for new models **define `props` from the real fields** for performance:
```dart
class User extends Model {
  final String id, name;
  User({required this.id, required this.name});
  factory User.fromJson(Map<String, dynamic> json) =>
      User(id: json["id"], name: json["name"]);
  @override Map<String, dynamic> toJson() => {"id": id, "name": name};
  @override List<Object?> get props => [id, name];   // override for perf
}
```

### API client — `lib/core/https/`, file `*_http.dart`
Extend `HttpConnection`, take a `BuildContext` in the constructor. Use the built-in `get/post/put/delete<T>()`. Handle `HttpErrorConnection` at the widget layer.
```dart
class UserHttp extends HttpConnection {
  UserHttp(BuildContext context) : super(context);
  Future<User> login(String username, String password) async {
    final resp = await post<ApiResponse>("/login", body: {"username": username, "password": password});
    if (resp.success) return User.fromJson(resp.result);   // note: the field is `result`, not `data`
    throw HttpErrorConnection(status: resp.status, title: "Login", message: resp.message ?? "");
  }
}
```
> Agent note: `ApiResponse.success` exists; the result field is named **`result`** (older README copy said `data` — that was wrong). See report §2.5.

### State — `lib/core/providers/` (global) or next to the widget (local)
Use Provider. **Always** add static `read`/`watch` helpers:
```dart
class FooProvider extends ChangeNotifier {
  static FooProvider read(BuildContext c) => c.read();
  static FooProvider watch(BuildContext c) => c.watch();
}
```
Register global providers in the `MultiProvider` in `main.dart`. Local providers: keep them in the same file as the widget, or in a `providers/` folder at the widget's level.

### Routing — `lib/core/utils/route.dart` (go_router)
Add a new `GoRoute` in `getRouter()`. Navigate with `context.goNamed("name")` / `context.pushNamed(...)`. The legacy `Navigator` helpers (`startScreen`/`replaceScreen`/`closeScreen`) in `navigations.dart` still exist for imperative, non-router pushes.

### UI — `lib/ui/`
Screens use `Scaffold`, small `const` widgets. Reuse: `CustomCard`, `CustomImage`, `ShimmerObject/ShimmeringObject`, `ColumnDivider/RowDivider`, `AdaptiveProgressIndicator`, `PaginatorPage<T>`. Loading dialog: `future.showProgress(context)` (extension). Dismiss keyboard: `widget.dismissKeyboardOnTap(context)`. Shared styles: `AppStyles.*` from `core/resources/styles.dart`.

### Config / environment — `lib/core/resources/environment.dart`
Subclass `AppConfig` (`DevelopmentMode`, `ProductionMode`). Access: `AppConfig.read(context)`. Swap at runtime: `AppConfig.switchConfig(context, config)`.

### Preferences — `lib/core/utils/preferences.dart`
`final p = await Preferences.instance(); p.token = "..."; final t = p.token;`. Setting `null` clears the value. Awaitable variant: `await p.saveToken("...")`.

### Logging
`clog(obj)` (pretty JSON for Map/List, debug only), `elog(obj)` (debug→console, release→Crashlytics), `cprint(obj)` (debugPrint). **Never** call `print()` directly.

## 5. Checklist before finishing (agent)

- [ ] `core`/`ui` split preserved; reuse existing utils/components.
- [ ] No hardcoded colors; use the theme helpers.
- [ ] New model: `toJson`/`fromJson` + per-field `props`.
- [ ] New API: `*_http.dart` extends `HttpConnection`, errors via `HttpErrorConnection`.
- [ ] New provider: `read`/`watch` helpers, registered if global.
- [ ] New route registered in `getRouter()`.
- [ ] `flutter analyze` clean, `dart fix --apply`, `flutter test` passing.
- [ ] No new force-unwraps (`!`) without a guard.
- [ ] Do not commit `firebase_options.dart` or any secret.

## 6. Fix status (see IMPROVEMENTS.md & DEEP_CHECK_REPORT.md)

Most of the old traps are **already fixed** (conservative style). Not yet verified with `flutter analyze` — run it locally before merging.

Fixed:
- ✅ `AppConfig.switchConfig` now copies the fields from `newConfig`.
- ✅ `Preferences.token` is null-safe; adds `saveToken`/`clearToken`/`clear` + `themeModeIndex`.
- ✅ `AdaptiveProgressIndicator` uses `kIsWeb`/`defaultTargetPlatform` (safe on Web).
- ✅ `ApiResponse.fromJson` has an optional `fromJsonT`; per-field `props`. The result field is still **`result`** (not `data`).
- ✅ Requests use Dio `queryParameters` (automatic encoding); `paramsToString` now URL-encodes.
- ✅ `DateTimeExtensions` use `String? locale` + resolve from `context`.
- ✅ `PaginatorPage` uses `ListView.builder` (lazy).
- ✅ `UserProvider` is registered globally; the `Bearer` token is injected automatically in `HttpConnection`.
- ✅ Theme is persisted (`ThemeProvider` ↔ `Preferences`), loaded in `Root.initState`.

Still the agent's responsibility:
- `Model.props` base is still `[toString()]` (intentional) — **always override `props` per field** in new models.
- Verify every change with `flutter analyze` + `flutter test` (the SDK was unavailable when the patch was authored).
- Endpoints are still hardcoded in `environment.dart` — consider `--dart-define` for secrets.
