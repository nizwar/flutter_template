# Flutter Template

A pragmatic Flutter boilerplate built on **Provider + go_router + Dio + Firebase**, with a clean `core` / `ui` separation, reusable components, and AI-agent guidance baked in.

> The contents of this repo are meant to live inside the `lib/` folder of a Flutter project (there is no `pubspec.yaml` at the template root). `firebase_options.dart` is `.gitignore`d and generated by `flutterfire configure`.

## Documentation map

- **`CLAUDE.md`** — the source of truth for AI agents (architecture, patterns, checklist). Read it first.
- **`DEEP_CHECK_REPORT.md`** — a full code audit (findings + recommendations).
- **`IMPROVEMENTS.md`** — what was fixed/added relative to that audit.
- Per-folder `readme.md` files — focused guidance for `core/https`, `core/models`, `core/providers`, `core/resources`, `core/utils`, `ui/components`, and `ui/screens`.

## Big rules

1. **Keep warnings at zero.** No deprecated or unused imports. Run `flutter analyze` and `dart fix --apply` before finishing.
2. **Stay current.** Periodically bump the SDK and packages; raise issues you hit instead of staying silent.
3. **Use Dev Tools.** Keep the widget tree shallow, profile memory, compress large assets (high-res images can OOM the app), and don't dump network logs to the console — use Flutter Dev Tools.
4. **Use and modify, but keep the structure.** Adapt the boilerplate to your app while preserving the folder layout and conventions so everyone stays aligned.

## AI instructions (read first)

Treat `CLAUDE.md` as the source of truth. In short:

1. Respect the architecture — keep the `lib/core` and `lib/ui` separation intact.
2. Reuse existing utilities/components before creating new ones.
3. Never hardcode colors; use the `ThemeData`/`ColorScheme` helpers.
4. Avoid deprecated/unused imports; keep warnings at zero.
5. Make clear, minimal diffs and keep naming conventions intact.

### Feature checklist

- **Models** → extend `Model` in `lib/core/models/` (override `props` per field).
- **APIs** → a `*_http.dart` file extending `HttpConnection`.
- **State** → Provider with static `read`/`watch` helpers.
- **UI** → `Scaffold` screens, reuse components, keep widgets small.
- **Resources** → theme helpers from `lib/core/resources/`.
- **Errors** → handle `HttpErrorConnection` at the widget layer.

## Project structure

```
lib/
├── main.dart                 # init Firebase/Crashlytics; MultiProvider; MaterialApp.router
├── root.dart                 # startup work (loads theme) → goNamed("home")
├── core/
│   ├── https/                # HttpConnection, ApiResponse, HttpErrorConnection
│   ├── models/               # Model base class + your models
│   ├── providers/            # global providers (ThemeProvider, UserProvider)
│   ├── resources/            # colors, themes, styles (AppStyles), environment
│   └── utils/                # app_config, route, navigations, preferences, logger, extensions
└── ui/
    ├── screens/              # SplashScreen, MainScreen, ...
    └── components/           # CustomCard, CustomImage, PaginatorPage, shimmer, ...
```

## App configuration

`AppConfig` manages environment-specific config (`appName`, `endpoint`, `color`). Subclass it per environment:

```dart
class DevelopmentMode extends AppConfig {
  DevelopmentMode() : super(appName: 'App title', endpoint: 'https://api.dev.com', color: Colors.blue);
}

class ProductionMode extends AppConfig {
  ProductionMode() : super(appName: 'App title', endpoint: 'https://api.prod.com', color: Colors.green);
}
```

Read it with `AppConfig.read(context)` and swap at runtime with `AppConfig.switchConfig(context, ProductionMode())`. (Consider `--dart-define` for secret endpoints rather than committing them.)

## Resources & theming

`USE THE THEME — DO NOT HARDCODE COLORS.` Derive everything from the active theme:

```dart
ThemeData   currentTheme       = theme(context);
TextTheme   currentTextTheme   = textTheme(context);
ColorScheme currentColorScheme = colorScheme(context);
```

Reusable styles live in `AppStyles` (`core/resources/styles.dart`): `inputDecoration`, `cardDecoration`, `pillDecoration`, `title`, `caption`. See `core/resources/readme.md`.

## State management

State is organized to avoid rebuilding an entire screen when a single widget changes. Provider is the default (BLoC is fine too if you prefer it). Whatever you choose, expose static `read`/`watch` helpers on every provider for consistent access. See `core/providers/readme.md`.

- **Global providers** (`UserProvider`, `ThemeProvider`) live in `lib/core/providers/` and are registered in `main.dart`.
- **Local providers** live next to their widget (single file) or in a sibling `providers/` folder.

## Networking

`HttpConnection` wraps Dio. Extend it per feature; the `Authorization: Bearer <token>` header is injected automatically from `UserProvider`.

```dart
class UserHttp extends HttpConnection {
  UserHttp(BuildContext context) : super(context);

  Future<User> login({required String username, required String password}) async {
    final resp = await post<ApiResponse>("/login", body: {"username": username, "password": password});

    // Example response wrapped by ApiResponse:
    // { "status": 200, "message": "Success", "result": {"name": "nizwar", ...} }

    if (resp.success) return User.fromJson(resp.result); // payload is in `result`
    throw HttpErrorConnection(status: resp.status, title: "Login", message: resp.message ?? "Login failed");
  }
}
```

Handle `HttpErrorConnection` at the widget layer. Full details in `core/https/readme.md`.

## Preferences

A thin wrapper over `SharedPreferences`:

```dart
final pref = await Preferences.instance();

pref.token = "XXXX";          // setter; passing null removes the key
await pref.saveToken("XXXX");  // awaitable variant
final String? token = pref.token;
await pref.clearToken();        // remove just the token
```

Stores `token` and `themeModeIndex` (used to persist the theme) out of the box.

## Widget utilities

- **Dividers** — `ColumnDivider` / `RowDivider` (default `space: 10`).
- **Shimmer** — `ShimmerObject`, `ShimmeringObject`, `ShimmerContainer`.
- **Custom Image** — `CustomImage` (cached, with placeholder/error handling, null-safe `url`).
- **Custom Card** — `CustomCard` for elevated surfaces with a soft shadow.
- **Paginator** — `PaginatorPage<T>` for pull-to-refresh + lazy infinite scroll.
- **Progress** — `AdaptiveProgressIndicator` (Web-safe) and `future.showProgress(context)`.

See `ui/components/readme.md` for the full API and examples.

## Navigation

Routing uses `go_router` (`core/utils/route.dart`): navigate with `context.goNamed("home")` / `context.pushNamed(...)`. Imperative helpers also exist for non-router pushes:

```dart
startScreen(context, YourScreen());     // push
replaceScreen(context, YourScreen());   // replace
closeScreen(context);                   // pop (optional result)
```

## Logging

Use `clog(obj)` (debug pretty-JSON), `elog(obj)` (debug → console / release → Crashlytics), and `cprint(obj)` (debugPrint). Never call `print()` directly.
